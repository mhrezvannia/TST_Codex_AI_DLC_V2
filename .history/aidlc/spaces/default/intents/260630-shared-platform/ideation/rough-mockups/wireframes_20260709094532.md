# Wireframes - Shared Platform Rough Mockups

## Purpose and Sources

These low-fidelity wireframes visualize the Shared Platform UI scope defined by `intent-statement.md`, `scope-document.md`, and `intent-backlog.md`. They cover only `apps/auth` and `apps/reference-data`. They do not include Charge, Booking, or Container Movement screens.

The frontend must follow Enterprise Technical Environment v1.1: Next.js App Router, BFF route handlers, TypeScript strict mode, Tailwind, TanStack Query, Zustand, RHF/Zod, shared `@erp/*` packages, App Router only, and `proxy.ts` route protection. Design-system basis is Enterprise Tech Env v1.1 plus the `@erp/ui` atomic-design component library; no separate LinerCore brand system has been provided yet.

## Screen 1 - apps/auth Sign In

Primary purpose: internal carrier staff authenticate through the enterprise Keycloak/OIDC path and enter the Shared Platform workspace.

```text
Header: LinerCore Shared Platform
Main:
  Sign in panel
    Title: Sign in
    Message: Use enterprise single sign-on
    Button: Continue with SSO
    Secondary text: Need access? Contact Security / IT
Status region:
  System notices and authentication errors
Footer:
  Privacy, support, environment label
```

States:

| State | Content |
|-------|---------|
| Empty/default | SSO button, support link, environment label. |
| Loading | Button disabled; inline status says redirecting to SSO. |
| Error | Plain-language error with retry action and support path. |
| Permission denied | User authenticated but lacks Shared Platform role; show request-access path. |

Accessibility note: one `h1` for Sign in, landmarks `header`, `main`, `footer`, first keyboard target is skip-to-main then SSO button, visible focus on the SSO button, error text announced with `aria-live="polite"`.

## Screen 2 - Reference Data Workspace Shell

Primary purpose: reference-data administrators maintain nine canonical reference sets from one consistent workspace.

```text
Header:
  LinerCore Shared Platform | User menu | Environment
Side navigation:
  Party / Customer
  Location / Port
  Region
  Voyage
  Currency
  Charge Code
  Equipment Type
  Commodity
  Trade Lane
Main workspace:
  Page title: [Reference set]
  Toolbar: Search | Filter | Add record
  List table: Code | Name | Status | Updated | Event status
  Detail panel: Selected record summary and actions
Right panel:
  Validation messages
  Last change event
  Replica freshness / sync status
```

States:

| State | Content |
|-------|---------|
| Empty list | Explain the reference set and show Add record if permitted. |
| Loading | Table skeleton and disabled toolbar. |
| Populated | Table, selected detail panel, event status. |
| Validation error | Field-level errors in text; preserve draft. |
| Permission limited | Read-only table and disabled Add/Edit actions with reason. |

Accessibility note: one `h1` for the current reference set, `nav` landmark for reference-set navigation, `main` for workspace, `aside` for validation/sync panel, table has caption and column headers, keyboard order moves nav to toolbar to table to detail panel to right panel.

## Screen 3 - Reference Record Create/Edit

Primary purpose: create or edit a canonical reference record with validation before saving.

```text
Main workspace:
  Breadcrumb: Reference Data > [Set] > [Record or New]
  Title: Edit [reference set]
  Form sections:
    Identity fields
    Classification fields
    Status and effective dates
    Notes / provenance
  Actions:
    Save draft
    Validate
    Publish change
    Cancel
Right panel:
  Validation results
  Required fields checklist
  Event preview: referencedata.[entity].changed
```

State examples by reference set:

| Reference set | Important fields / validation focus |
|---------------|--------------------------------------|
| Location / Port | Country-Port containment; no orphan Port. |
| Region | Flat grouping assigned over locations. |
| Trade Lane | Origin Region and Destination Region. |
| Voyage | Schedule and nominal capacity. |
| Party / Customer | PII handling and role assignment. |

Accessibility note: `h1` is Edit [reference set], form sections use `h2`, every input has a visible label, errors are text plus icon and not color-only, buttons are keyboard reachable, destructive or publishing actions require confirmation.

## Screen 4 - Event and Sync Status

Primary purpose: let admins and operators verify that a reference change was published and consumers can track freshness.

```text
Header:
  Reference set and selected record
Main:
  Change history table
    Time | User | Change type | Event ID | Status
  Event details panel
    Type
    Correlation ID
    Schema version
    Published time
    Consumer freshness target
Actions:
  Recheck status
  Copy event ID
  Open troubleshooting notes
```

States:

| State | Content |
|-------|---------|
| Published | Event ID, schema version, publish time, status. |
| Pending | Outbox pending notice and next retry time. |
| Failed | Plain-language failure with operator escalation path. |
| Stale replica | Freshness SLA warning once the SLA is defined. |

Accessibility note: `h1` is Event and Sync Status, event status changes use `aria-live`, table has caption and headers, Copy event ID has accessible name, status is expressed with text and icon, not color alone.

## Screen 5 - Responsive Read-Only View

Primary purpose: allow quick reference lookup from tablet/mobile without making mobile editing the primary workflow.

```text
Mobile header:
  Menu | Reference Data | User
Main:
  Search
  Reference set selector
  Result list
  Selected record details
Actions:
  Copy ID
  View event status
```

Mobile behavior:

| Area | Behavior |
|------|----------|
| Navigation | Collapses to menu and reference-set selector. |
| Table | Converts to stacked result cards with key fields. |
| Detail panel | Opens as page section below the selected result. |
| Editing | Read-only by default unless later requirements explicitly allow mobile editing. |

Accessibility note: heading hierarchy remains `h1` then `h2`, menu button exposes expanded state, touch targets meet minimum size, all controls remain keyboard and screen-reader operable.

## Information Architecture

| App | Primary routes | Notes |
|-----|----------------|-------|
| `apps/auth` | `/signin`, `/callback`, `/access-denied`, `/signout` | BFF-backed session handling and Keycloak redirects. |
| `apps/reference-data` | `/`, `/sets/[set]`, `/sets/[set]/[id]`, `/sets/[set]/new`, `/events/[eventId]` | Shared workspace shell with reference-set specific content. |

## Out of Scope for Mockups

- Charge, Booking, and Container Movement screens.
- Customer self-service identity or track-and-trace screens.
- Detailed visual design, colors, typography tokens, or final component specs.
- Implementation-specific API payloads beyond event/type labels already in approved scope.
