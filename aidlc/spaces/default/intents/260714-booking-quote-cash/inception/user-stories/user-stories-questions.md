# User Story Plan Questions - W1-01

## Q1 - Persona Set

Which persona set should structure the stories?

A. Customer-service agent as primary plus intent release reviewer for live evidence (recommended)
B. Customer-service agent only; keep release evidence outside stories
C. Customer-service agent plus separate Booking, Charge, and CMM technical personas
X. Other (please specify)

`[Answer]:` A - Customer-service agent as primary plus intent release reviewer for live evidence.

## Q2 - Breakdown Approach

How should the story set be organized?

A. By end-to-end workflow increments and recovery outcomes (recommended)
B. By service/domain ownership
C. By frontend versus backend layers
D. By requirement ID one-for-one
X. Other (please specify)

`[Answer]:` A - Organize by end-to-end workflow increments and recovery outcomes.

## Q3 - Granularity

What granularity best balances INVEST independence with the inseparable release spine?

A. Seven focused vertical stories: create, validate, price, confirm/journey, status/detail, resilience, release proof (recommended)
B. Four larger stories combining adjacent workflow steps
C. Ten or more smaller stories split by happy/error paths
X. Other (please specify)

`[Answer]:` A - Use seven focused vertical stories: create, validate, price, confirm/journey, status/detail, resilience, and release proof.

## Planned Format and Priority

Stories use "As a [persona], I want [goal], so that [benefit]", Given/When/Then criteria, MoSCoW priority, requirement trace, dependencies, and an INVEST note. The formal MVP decision remains Delivery Planning, but the seven W1 spine stories are expected to be Must Have.
