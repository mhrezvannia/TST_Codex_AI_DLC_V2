# Mob Composition - W2-04

## Mob charter

One stream-aligned intent mob delivers the vertical outcomes in
`intent-backlog.md`, within `scope-document.md` and
`feasibility-assessment.md`. The mob owns delivery, not every neighboring
contract or shared asset.

## Roles and decision rights

| Role | Accountable decision |
|---|---|
| Intent driver / product navigator | Scope, sequence, dependency escalation |
| CMM domain lead | Journey invariants and producer-owned status meaning |
| Booking reviewer | Consumer compatibility, projection, Booking evidence |
| UI/UX reviewer | Container Movement page composition; LinerCore compliance |
| Quality/release reviewer | Test strategy, evidence integrity, stack lock, audits |
| Platform/security reviewer | Broker/schema/outbox health, RBAC, audit controls |
| W2-02 owner | Shared UI primitives/master; synchronization sign-off |

Driver/navigator roles rotate during implementation; one navigator speaks at a
time. Focused solo research is allowed, but decisions return to the mob record.

## RACI and interactions

CMM is accountable for status production; Booking is consulted and co-signs
consumer-impacting changes. W2-02 is accountable for shared UI and collaborates
only for final synchronization. Release review is accountable for serialized
live acceptance and demo protection. W2-03 remains informed where integration
timing overlaps, without shared implementation ownership.

## Capacity agreement and onboarding checklist

- Confirm role coverage before Construction; do not infer named availability.
- Keep one accountable driver across PB-01 through PB-04.
- Acquire the Wave A stack slot before live acceptance.
- Load contracts, Context Pack, W1 PASS/waiver distinction, Graphify findings,
  and UI master/session prompt.
- Escalate contract, shared-UI, or stack conflicts to their bounded owner.
- Record handoffs and decisions in AI-DLC artifacts/audit so location and
  timezone assumptions are unnecessary.
