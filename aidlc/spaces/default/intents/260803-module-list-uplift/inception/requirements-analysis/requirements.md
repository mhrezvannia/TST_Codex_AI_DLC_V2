# Requirements — W4-01 Module List-Detail Uplift

## Intent Analysis

W4-01 is a brownfield product-coherence enhancement, not a new domain-capability program. It enables Reference administrators, Pricing analysts and Charge readers, and Container-operations users to find real records, inspect stable detail pages, perform only currently supported actions, and follow exact related records without leaving the single authenticated LinerCore shell.

The binding sources are `intent-statement.md`, `scope-document.md`, the Reverse Engineering `business-overview.md`, `architecture.md`, and `code-structure.md`, the affirmed `team-practices.md`, the LinerCore page contracts, and the seven decisions in `requirements-analysis-questions.md`. The approved sequence is Reference Data, then Charge Agreements, then Container Journeys; W4 closes only after all three operate together on the isolated live stack.

### Legacy Route Retirement Matrix

All permanent redirects use HTTP 308. Redirect handlers retain only the listed query state after validation and drop every unknown key. `returnTo` is limited to 2,048 decoded characters and must be a relative, same-shell canonical list path with its module's allow-listed filter/page/focus keys; schemes, hosts, protocol-relative paths, backslashes, control characters, encoded separators, and traversal segments are rejected. Invalid identifiers or context never redirect to a guessed record.

| Existing source path | W4 outcome | Canonical target | Allow-listed carried query keys | Invalid / ambiguous outcome |
|---|---|---|---|---|
| `/reference-data` | 200; replace legacy workbench composition in place | `/reference-data` | Reference list owns `setCode`,`includeInactive`,`page`,`size`,`focus`; only provider-supported keys render controls | Invalid query is canonicalized by dropping invalid/unknown values; no redirect to a guessed set or record. |
| `/charge-agreements` | 200; replace root workbench composition in place | `/charge-agreements` | `customerId`,`tradeLaneId`,`commodityId`,`status`,`validOn`,`includeInactive`,`page`,`size`,`focus` | Invalid query is canonicalized by dropping invalid/unknown values. |
| `/charge-agreements/agreements/new` | 308 | `/charge-agreements/new` | validated `returnTo` only | Unsafe context is dropped; target remains canonical New. |
| `/charge-agreements/agreements/[agreementId]` | 308 | `/charge-agreements/[agreementId]` | validated `returnTo`,`tab` | Empty, malformed, encoded-separator, or ambiguous ID returns 404. |
| `/charge-agreements/agreements/[agreementId]/edit` | 308 | `/charge-agreements/[agreementId]/edit` | validated `returnTo`,`tab` | Empty, malformed, encoded-separator, or ambiguous ID returns 404. |
| `/charge-agreements/agreements/[agreementId]/successor` | 308 | `/charge-agreements/[agreementId]/successor` | validated `returnTo`,`tab` | Empty, malformed, encoded-separator, or ambiguous ID returns 404. |
| Any other Reference or Charge path alleged to be legacy | No compatibility route | none | none | 404. The current inventory proves no exact retired path requiring 410; a 410 may be added only by approved change control with evidence of a previously published, intentionally removed path. |
| Any Container Movement legacy-looking path | No compatibility route | none | none | 404; there was no prior Container Movement frontend, so W4 creates no redirect. |

## Data & Standards Alignment

| Domain | Canonical data and standards requirement |
|---|---|
| Reference Data | `setCode`, provider-stable `recordId`, readable code/label, active/effective state, version, validity, and change history remain owned by the Reference provider. UN/LOCODE, ISO equipment, SMDG, or other code sets retain their provider-defined code plus readable meaning. |
| Charge Agreements | `agreementId`, agreement/rate version, lifecycle status, validity, charge code/category, rate basis, quantity, amount, and ISO 4217 currency retain current Charge contract meaning. Approved commercial history remains immutable; `MANUAL_PRICING_REQUIRED` remains evidence, not a zero price or invented workflow. |
| Container Movement | `journeyId`, `bookingId`, ISO 6346 equipment identity where present, route/location facts, and DCSA-aligned GTOT, LOAD, DISC, and GTIN event codes retain W2-04 contract meaning. Every code is paired with a readable label, occurred/received time, source, and ordering/validation meaning where applicable. |
| URLs and context | Route identifiers are provider-stable. List context contains only allow-listed internal query fields; it is navigation state, not a second source of domain truth. |
| Audit evidence | Correlation, provider reference, version, and source timestamps remain evidence metadata. Raw payloads are never substituted for labelled operational fields. |

No W4 frontend may rename a canonical contract field, calculate a new domain status, join service databases, or copy provider data ownership into UI state.

| Contract or seam | Producer | Consumer | Style | W4 requirement |

| Agreement list/detail/actions | Charge Agreement service | Charge BFF/UI | Synchronous HTTP | Reuse mature routes/contracts; preserve version, rate, D&D, lifecycle, and error meaning. |

### Cross-Link Direction Matrix

Every present relationship opens the exact canonical record in the single shell. An absent relationship renders concise text such as `No linked booking` or `Journey not created`; it does not render a disabled or guessed link. A denied target still uses the shared denied route state. The acceptance fixture set contains one present, one absent, one denied, and one stale/dependency-failure case per implementable direction.

| Direction | Current identifier evidence | Binding W4 behavior | Status / owner / exit condition |
|---|---|---|---|
| Agreement -> Booking | Current Agreement detail/version contracts expose commercial terms but no authoritative related `bookingId` collection; manual-pricing `bookingRef` is exception evidence, not a general Agreement relationship | Do not offer a Booking link or reverse-search Bookings from labels/customer/lane. Display `Related bookings unavailable` only where the design reserves the relationship region. | `BLOCKED` — Charge Agreements + Booking owners. Exit requires approved scope change and an additive producer-owned Agreement-to-Booking relationship/read projection carrying stable `bookingId`, plus dual-signed contract and live link tests. |
| Booking -> Agreement | Typed Booking pricing evidence exposes `agreementVersionId`; it does not expose the parent stable `agreementId`, and the canonical route cannot safely treat a version ID as an agreement ID | Do not build `/charge-agreements/[agreementVersionId]`. For tariff pricing show `Tariff pricing`; for agreement pricing without resolvable parent show `Agreement link unavailable` while retaining the version evidence. | `BLOCKED` — Booking + Charge Agreements owners. Exit requires approved scope change and either additive `agreementId` in the Booking snapshot or a producer-owned version-to-agreement resolver, then dual-signed executable contract/live link tests. |
| Journey -> Booking | Journey detail exposes verified stable `bookingId` | Render `/booking/[bookingId]` with validated bounded origin context; absent ID is a provider contract failure, not a search prompt. | Required and implementable with the current CMM detail contract. | Booking -> Journey | Current CMM provider supports lookup by verified `bookingId` and returns the authoritative journey, including stable `journeyId` | The Booking server/BFF performs the authorized provider lookup and renders `/container-movement/journeys/[journeyId]` only from its result.
