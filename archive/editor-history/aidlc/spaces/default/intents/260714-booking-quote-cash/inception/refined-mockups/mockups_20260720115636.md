# Refined Mockups - W1-01 Booking Quote-to-Cash

## Visual Frame

Booking remains a local operational app until W2-01 migrates it into the global shell. Every route uses the W2-02 visual language already present in `@erp/ui`: neutral work surface, navy primary anchors, teal success, amber pending/manual states, red blocking errors, IBM Plex Sans/Mono, compact density, 6-8px radii, and zero decorative gradients/orbs. Content sections are unframed bands; only dialogs and genuinely bounded repeated items use card treatment.

Wide pages constrain content to a readable operational width while the quote/action rail remains visible. Tablet collapses the rail below the lifecycle header. Mobile stacks sections in workflow order and preserves a sticky bottom action bar without covering content.


All reference fields are live `Combobox` controls with code + label. Quantity and USD are visible fixed values, not hidden assumptions. `equipmentId` is required and validated as ISO 6346. Create stays disabled until local shape is complete; server validation remains authoritative. Failed submission preserves every value, focuses the error summary, and links each summary item to its field. Success navigates to the stable detail route and announces `Booking created`.

On mobile, each group becomes a full-width unframed section and the action bar is sticky above the safe area. It reserves layout space so fields are never obscured.

## Booking Detail - `/bookings/{bookingId}`

```text
[Back] BKG-204418  Rev 1  [CONFIRMED]                         [Refresh icon]
Pacific Rim Trading | CNSHA -> NLRTM | Updated 10:44

Request [done]  Validate [done]  Price [done]  Confirm [done]  Journey [current]

[Overview] [Routing] [Equipment] [Charges] [Journey] [Audit]

JOURNEY                                           QUOTE
[Journey active]                                  USD 4,764.00
LOAD | PLN | CNSHA | APZU4812090                  Agreement AGR-1042
Planned 28 Jun 09:12 | received 10:44             3 line items
                                                  No action required
```

The header and lifecycle strip remain outside tabs. Tabs contain real domain relationships:

- **Overview:** customer, status, revision, route/equipment/quote summaries.
- **Routing:** ordered leg table with UN/LOCODE and voyage.
- **Equipment:** type, quantity, ISO equipment ID.
- **Charges:** itemized charge code/category/amount/currency and pricing basis.
- **Journey:** pending/active movement state, DCSA code/classifier/time/location.
- **Audit:** collapsed-by-default correlation, lifecycle history, event IDs, and last checks; no offsets/schema IDs in primary views.

The quote rail is an `aside` with a border separator, not a nested card. It presents only the next valid action: Validate, Price, or Confirm. Confirm opens a focused dialog naming booking, route, equipment, and total. After submit, the dialog closes, focus returns to the page heading, and the Journey tab becomes selected only if the user was already on it; otherwise a status announcement offers a direct `View journey status` link.

## Detail Lifecycle States

| State | Header/rail | Main content | Recovery |
|---|---|---|---|
| Draft | Draft; Validate primary | Overview editable only through future amendment scope; current data read-only | Validate |
| Validation blocked | Validation failed | Summary links to failed canonical references | Return/create correction path |
| Validated | Price primary | References marked verified | Price |
| Pricing pending | Disabled rail with progress | Charges skeleton; previous data retained | Automatic |
| Manual pricing | Amber Manual badge; Confirm disabled | Reason and correlation in Charges | Retry pricing |
| Priced | Confirm primary | Itemized quote and agreement basis | Confirm dialog |
| Confirm pending | Confirmed; no duplicate action | Journey pending with last checked | Auto poll / Retry |
| Journey active | No primary lifecycle action | Latest contract-valid movement status | Manual refresh |
| Detail unavailable | Header skeleton or known booking header | Inline alert; no fallback data | Retry / Back |
| Not found | No fake booking | `Booking not found` | Back to list |

## Pending Journey Transition

Immediately after confirmation, the Journey section renders:

```text
[Pending] Confirmation accepted. Waiting for Container Movement Management.
Last checked 10:43:08                                        [Stop] [Retry disabled]
```

While the document is visible/focused, detail polls every second for at most 30 seconds. A successful status update stops polling, updates `Last updated`, and announces `Journey status received` through a polite live region. Visibility loss pauses the timer; focus/visibility return resumes only within the original 30-second budget. At timeout:

```text
[Still pending] No status has arrived yet. The booking remains confirmed.
Last checked 10:43:38                                               [Retry]
```

Retry starts a new bounded 30-second cycle. The agent is never told confirmation failed merely because CMM status is delayed.

## Responsive Layouts

| Width | List | Create | Detail |
|---|---|---|---|
| >= 1200px | Full table/filter row | Two-column routing/equipment fields inside full-width groups | Content + 320px quote rail |
| 768-1199px | Priority columns; secondary metadata below ref | One/two columns based on available space | Quote summary below lifecycle; horizontally scrollable tabs with visible focus |
| 360-767px | Semantic stacked rows, not a squeezed table | Single column + reserved sticky actions | Header stack; tabs scroll; quote collapsed after lifecycle |

No font scales with viewport width. Long customer names truncate only where a full accessible name remains available. Booking/UN-LOCODE/equipment codes use mono type and wrap only at safe separators.

## Review

**Verdict: READY**

Inline product-lead recovery review completed after two independent reviewer processes timed out without editing an artifact. This verdict is therefore not independent.

- The list, create, and detail designs cover all seven Must Have stories, including live reference selection, validation, pricing fallback, confirmation, returned journey status, replay/restart evidence, and release proof.
- Lifecycle actions, loading/empty/error/partial states, bounded CMM polling, and recovery behavior are specific enough for implementation and acceptance testing.
- `interaction-spec.md` preserves the Booking-local W1 boundary, contract-valid field semantics, server idempotency, and the approved 5-second visible-status target without introducing the W2-01 shell.
- `design-system-mapping.md` reuses W2-02 tokens and `@erp/ui` primitives, limits new shared capability, and keeps transport internals out of the primary operator journey.
- `accessibility-checklist.md` defines WCAG 2.1 AA, keyboard, announcement, contrast, responsive, and no-overlap gates with executable verification methods.
- `refined-mockups-questions.md` contains no unresolved answer and matches the generated artifacts.

No blocking product, interaction, accessibility, responsiveness, scope, or traceability issue remains for Application Design.
